# `src/evaluation/` - Metrics, Confidence Intervals, Hypothesis Tests

**Status:** `metrics.py`, `hypothesis.py`, and `drift_detectors.py` populated and unit-tested, and consumed by the RQ1 through RQ5 notebooks (`12` through `16`), the feature ablations (`18`), and the cross-cutting evaluation notebooks (`17`) for every reported metric, threshold test, and the family-wise correction; the RQ4 notebook additionally uses `brier_score_with_ci` and `calibration_table` for the at-submission probability calibration and `paired_wilcoxon_cv` for the 25% efficiency-improvement test, and the RQ5 notebook uses the drift detectors plus the custom drift metrics. The family-wise correction in `17_hypothesis_testing.py` uses the bootstrap threshold p-value added to `metrics.py` (below), and `17_shap_analysis.py` runs the SHAP interpretability and tier-alignment analysis directly, since the per-checkpoint handling is notebook-specific and no reusable `interpretability.py` module was warranted. Reusable metric helpers landed early so the per-RQ notebooks share one canonical implementation of each metric.

## Modules

- `metrics.py`, populated - Canonical metrics, each returned as `(point, ci_low, ci_high)`: `mcc_with_ci` (the primary metric per Chicco & Jurman, 2023), `f1_with_ci`, `pr_auc_with_ci` (Saito & Rehmsmeier, 2015), `roc_auc_with_ci`, `brier_score_with_ci`, plus `calibration_table` (reliability bins and observed-vs-predicted, a TRIPOD+AI calibration item, `P18`). The 95% confidence interval is a stratified percentile bootstrap (1,000 resamples by default; positives and negatives resampled independently to preserve class balance and keep both classes present for the AUC metrics, `P15`). Inputs accept Polars Series, NumPy arrays, or lists; the label metrics take `y_pred` already at the chosen operating point and the score metrics take `y_score`. For the family-wise correction, `bootstrap_threshold_pvalue(replicates, threshold, greater_is_better=...)` returns the one-sided share of resamples that fail to clear the target, and every `*_with_ci` function accepts `return_replicates=True` to expose the resample distribution it is read off, so the interval and the p-value come from one and the same bootstrap (`V56`). Tested in `tests/test_metrics.py`. The bootstrap engine lives inside this module, so there is no separate `bootstrap.py`.
- `hypothesis.py`, populated - `one_sample_threshold_test` (the CI-based one-sided decision committed in Chapter 3: reject only when the (1 - alpha) CI lower bound clears the target), `paired_wilcoxon_cv` (signed-rank comparison of two models across the same CV folds, with the small-fold power caveat stated), `cohens_d` (pooled effect size), and the family-wise corrections `holm_bonferroni` (primary) and `benjamini_hochberg` (supporting) for control across the five RQs (`P16`). Each returns a plain dict that serializes into `outputs/tables/`. Tested in `tests/test_hypothesis.py`.
- `metrics.py` also carries the custom drift metrics the Chapter 3 Custom Metrics subsection commits to: `performance_degradation_rate` (OLS slope of MCC over months; negative means the model is going stale), `drift_detection_latency` (signed days between an onset estimate and detection, negative when the detector fires first, which is reported rather than clipped), `retraining_effectiveness` (recovery share), `performance_sustainment_window` (consecutive months at or above a bar), `sustainment_reference` (a reachable bar at a fraction of a model's own initial MCC), and `mcc_at_fixed_prevalence`. The last two exist because of `V54` and `V55`: a sustainment window measured against the locked 0.85 target is 0 for every strategy on Backblaze and so cannot distinguish them, and MCC is prevalence-sensitive while the Backblaze failure-day rate falls roughly threefold across the evaluation window, so a raw year-over-year MCC series confounds prior shift with the covariate drift it is meant to measure. `mcc_at_fixed_prevalence` holds the base rate constant by discarding (never duplicating) from the over-represented class; report it alongside the raw series, never instead of it.
- `drift_detectors.py`, populated - Four detectors behind one `update` / `drift_detected` / `warning_detected` / `reset` interface, each logging `drift_indices` so detection latency against a known onset is computable. `ADWINDetector` and `PageHinkleyDetector` wrap River and consume a per-observation loss (sudden drift, `P12`); `KSDriftDetector` and `PSIDriftDetector` compare a sliding feature window against a reference window (gradual drift and covariate shift). Each detector takes one scalar signal, so multivariate monitoring is one detector per feature with the flags aggregated by the caller, which preserves the per-feature attribution the drift narrative needs. Two defaults are derived from the data rather than inherited from the library and are pinned by tests: Page-Hinkley (`delta` 0.01, `threshold` 15), because the excursion scale of a Bernoulli loss is `p(1-p)/(2*delta)` and the library-typical settings false-alarm on a stationary 5% error stream; and a `PSIDriftDetector` constructor guard that refuses window sizes where the statistic's sampling-noise floor, about `(n_bins-1)*(1/n_ref + 1/n_win)`, exceeds its own drift band (a 30-observation 10-bin window has an expected null PSI near 0.6 against a 0.25 band, so it would flag every window). `population_stability_index` and `expected_null_psi` are exported for direct use; PSI carries a zero-inflation branch for the median-zero SMART attributes. Tested in `tests/test_drift_detectors.py`. Known limitation from `V55`: the window detectors skip non-finite values by construction, so they measure shifts in the values that are present and cannot see an availability (missingness) shift; monitor the populated rate directly for that case.
- Calibration and Brier-score helpers are part of `metrics.py` (`calibration_table` and `brier_score_with_ci`), not a separate `calibration.py`.
- `interpretability.py` - not extracted. Sample-based SHAP (`P17`) and the tier-alignment analysis run directly in `17_shap_analysis.py`, because the attribution is specific to each frozen checkpoint (a single fitted pipeline for Google, a three-member soft-voting stack explained per member for Backblaze) rather than a reusable transform. The global rankings, tier-alignment table, and figures are written to `outputs/tables/` and `outputs/figures/shap/`.

## Cross-cutting conventions

- The label metrics (`mcc_with_ci`, `f1_with_ci`) take `y_pred` already thresholded at the chosen operating point; the score metrics (`pr_auc_with_ci`, `roc_auc_with_ci`, `brier_score_with_ci`) and `calibration_table` take `y_score`. Functions never read a threshold from a global; the caller selects the operating point upstream.
- Every reported metric in `outputs/tables/` carries its bootstrap CI; the bootstrap helper is the single source of truth.
- Hypothesis-test results write to `outputs/tables/hypothesis_tests.csv` with one primary row per RQ (plus reported secondary rows), including raw p, Holm-adjusted p, BH-adjusted p, effect size, and decision. Because `one_sample_threshold_test` implements the Chapter 3 rule as a CI comparison and emits no p-value, the family-wise step needs a p-value source; this is resolved (`V56`). `bootstrap_threshold_pvalue` is the reusable source-side companion (the share of resamples not clearing the threshold, off the exposed replicate array), and `17_hypothesis_testing.py` derives each frozen result's family p-value from its stored percentile interval by a normal-tail approximation against the target. All five primary outcomes are decisive, so Holm and Benjamini-Hochberg agree with the CI rule and change no decision.
- Any metric compared across time periods is reported at a fixed prevalence as well as raw, because the primary metric is prevalence-sensitive and the Backblaze base rate moves materially across the evaluation window (`V55`).
- Reporting follows TRIPOD+AI item 23 (calibration), item 24 (discrimination), and item 25 (uncertainty quantification).

Modules land here once the corresponding RQ has at least one validated result and the metric / CI pattern stabilizes.
